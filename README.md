# 차트 발굴기 (chart_screener)

KOSPI·KOSDAQ 전 종목의 일봉을 분석해 기술적 매수 패턴을 찾는 스크리너입니다. 결과는 인터랙티브 HTML 리포트
(차트 위에 패턴·피벗 표시)와 엑셀/CSV 로 저장되며, 매일 실행하면 전일 대비 신규·돌파·탈락을 표시합니다.

**2026-10-14 패턴 초기화**: 옛 탐지기 13개(CAN SLIM · VCP · 옛 컵앤핸들 · 장기횡보 돌파 · 300억 눌림목 · 플랫 베이스 ·
더블 바텀 · 하이 타이트 플래그 · 3주 타이트 · 포켓 피벗 · 트렌드 템플릿 · 바닥 투매 흡수 · 바닥 탈출)를 지웠습니다.
남긴 패턴은 **컵 앤 핸들 — 사용자 식(`cwh_reference_v1.0.0`)** 과 관찰 칩(보컬 · 저평가 종목)이고, 같은 날
**《차트의 기술》 영상 기법 6개**(빗각 추세선 돌파 · 피보나치 눌림 반등 · 빗각 돌파 + 피보 눌림 · 60일선 수급 돌파 · 월봉 적삼병 ·
10% 주도주)를 더했습니다 — 아래 '《차트의 기술》 영상 기법'. 새 기법은 모두 **우리 데이터로 검증하기 전**입니다.
옛 탐지기의 스캔 일지 기록 · 백테스트 수치는 지우지 않고 '옛 패턴 기록'으로 따로 둡니다(아래).

> 기술적 패턴 탐지와 과거 통계를 보여주는 도구이며 투자 권유가 아닙니다.

## 빠른 시작

```bash
pip install -r requirements.txt
python -m chart_screener scan --open        # 전 종목 스캔 → output/scan_YYYYMMDD_HHMM.html 열기
```

Windows 에서는 `scan.bat` 더블클릭으로도 실행됩니다. 첫 실행은 약 2,400종목 일봉을 받느라 2~3분 걸리고,
이후에는 캐시(`cache/`)를 써서 장 마감(15:45) 후 한 번만 새로 받습니다. 장중에는 20분마다 갱신합니다.

| 명령 | 하는 일 |
|---|---|
| `python -m chart_screener scan` | 전 종목 스캔 → HTML·엑셀·CSV (`output/`), 스캔 일지 기록 |
| `python -m chart_screener scan --offline` | 네트워크 없이 캐시로만 (증권사 자료도 끔) |
| `python -m chart_screener scan --kis auto` | 기본값. 한국투자증권 설정·토큰이 되면 증권사 자료(종목 상태 · 실제 거래대금 · 수급 · 목표가 · 추정실적)를 쓰고, 안 되면 이유를 보여 주고 네이버로 계속 |
| `python -m chart_screener scan --kis on` / `--kis off` | 증권사 자료 필수(안 되면 종료 코드 1) / 끔(네이버만) |
| `python -m chart_screener scan --skip-holiday` | 오늘이 휴장일이고 캐시 최신 봉이 이미 직전 개장일이면 `휴장일 — 스캔하지 않음` 을 찍고 리포트 없이 끝냄 (작업 스케줄러용) |
| `python -m chart_screener scan --account 30000000 --risk 1` | 계좌 3천만 원, 1회 손실 1% 기준으로 수량 계산 |
| `python -m chart_screener scan --patterns cup_with_handle` | 일부 패턴만 (일지는 쓰지 않음) |
| `python -m chart_screener analyze 005930 --open` | 한 종목의 모든 패턴 판정 근거(충족 ✔ / 미충족 ✘) |
| `python -m chart_screener market` | KOSPI·KOSDAQ 시장 방향(분산일·팔로스루데이·시장 폭) |
| `python -m chart_screener track` | 지난 스캔 후보들의 실제 5·20·60일 성과 집계 (일지 기반 사후 검증). 손절먼저% · +20%먼저% 는 손절가 있는 행만 — 손절 규칙 없는 컵 앤 핸들 행은 outcome `no_stop`, '손절 규칙 없음'으로 따로 적음 |
| `python -m chart_screener backtest cup_with_handle` | 과거 돌파 신호 성과 (미래 참조 없는 워크포워드). 사전 필터 없이 매일 판정해 오래 걸림. 컵 앤 핸들은 손절 규칙이 없어 '손절 0%' 대신 `손절 규칙 없음 — 손절 비율 해당 없음 · 60봉 안 +20% 도달 X%` 로 찍음 |
| `python -m chart_screener backtest fib_pullback` | 《차트의 기술》 기법 신호 성과 — `trendline_break` · `trendline_fib` · `ma60_supply` · `red_three_monthly` 도 같은 꼴. 신호일 · 사전 필터 · 손절 판정은 기법마다(아래 '《차트의 기술》 영상 기법' 표). `day_leader` 는 `--mode stage --stages near_pivot` 만 |
| `python -m chart_screener live` | 장중 실시간 감시: 후보 + 증권사(한국투자증권)/네이버 시세 → 피벗 근접·돌파 알림 (조회 전용, 아래 참고 — 지금 패턴은 손절 · 눌림 알림을 내지 않음) |
| `python -m chart_screener news --codes 010170,005930` | 종목 뉴스 제목(한국투자증권, 조회 전용) → `cache/kis/news/<code>.json` — 기업추적 '내러티브' 탭용 (아래 참고) |

### 일봉 이력 기간 (기본 3년 → 최대 약 10년)

기본은 3년치(760봉)를 받습니다. 더 길게 보려면 `--years` 를 붙이세요. 캐시가 짧으면 자동으로 다시 받습니다.

```bash
python -m chart_screener scan --years 10 --open
```

- 10년치: 전 종목 다운로드 약 2분 20초(최초 1회), 리포트 약 8MB(후보 50여 종목), 캐시 약 280MB. 스캔 시간은 2026-10-14
  패턴 초기화 뒤 10년치로 다시 재지 않았습니다(예전 '약 30초'는 옛 탐지기 시절 값). 3년치 실측(2026-10-14, 캐시만):
  패턴 판정 약 45초(860종목 · 컵 앤 핸들 식 종목당 약 50ms) + 캐시 적재 · 시장 계산 포함 전체 약 2분.
- 리포트 차트는 기본 3년 보기이고 `6개월 · 1년 · 2년 · 3년 · 5년 · 10년 · 전체 · 패턴 구간` 버튼으로 바꿉니다.
- 항상 10년으로 쓰려면 `scan.bat --years 10` 으로 실행하거나 `chart_screener/config.py` 의
  `history_days` 를 `bars_for_years(10)` 으로 바꾸세요. 옵션 없이 온라인 실행하면 3년치로 다시 받습니다.
- 백테스트도 `python -m chart_screener backtest cup_with_handle --years 10` 으로 2017년부터 검증할 수 있습니다(시간은 길이에 비례).
- 10년 이전 거래량은 액면분할 미반영 원거래량이라 오래된 구간일수록 거래량 비교가 왜곡될 수 있습니다.

### 차트 긴 이력 — 상장 이후 전체 (증권사 일봉, 리포트를 뷰어로 열 때)

패턴 판정은 위 일봉(기본 3년)으로 하고, 리포트 차트의 `5년 · 10년 · 전체` 는 상장 이후(1990년~) 이력으로 그립니다
(`chart_screener/chart_history.py`). 네이버 일봉 조회는 최근 약 12년(2014년~)까지만 주므로, 그 앞은 한국투자증권
일봉 조회(수정주가, 1회 100봉)로 종목마다 한 번 받아 `cache/kis/hist/<code>.json` 에 둡니다.

- `scan` 이 리포트를 쓴 뒤, 리포트에 차트가 담긴 종목(후보 상위 · 저평가 비후보 차트)마다 리포트 옆 `hist/<code>.json`
  (앞 긴 이력 + 스캔 일봉)을 씁니다. 리포트는 종목을 열 때 이 파일을 불러와 차트를 늘리고 이동평균도 늘린 이력으로
  다시 계산합니다. 기간 버튼 옆에 `1987-05-27부터 (상장 이후 · 증권사 일봉)` 처럼 첫날이 보입니다.
- 오래 상장한 종목은 처음에 수십 번 호출합니다(S-Oil 1987년~ 약 96회 · 1분 30초 — 증권사 일봉 응답이 회당 약 1초,
  동시 2개 넘게 부르면 초당 한도에 걸림). 스캔마다 `--hist-budget` 초 안에서 순위 높은 종목부터 받고, 남은 종목은
  다음 스캔에서 이어 받습니다. 기본 0(끔) — 파일로 연 리포트는 어차피 못 읽으므로, 기업추적 뷰어가 '차트 발굴'
  스캔에 `--hist-budget 600` 을 붙입니다(결과 표 · 리포트를 낸 뒤에 받음).
- 한 번 받은 앞 구간은 다시 묻지 않습니다(스캔 일봉 창이 앞으로 가면 빈 날만, 끝까지 닿았을 때만 '받은 마지막 날'을
  올림). 수정주가 조정(분할 · 증자)으로 겹치는 구간 종가가 0.5% 넘게 어긋나면 받아 둔 앞 구간을 그 비율로 맞춰 다시
  저장합니다(가격만 — 거래량은 스캔 일봉처럼 조정 전 주식 수). 거래정지일 등 가격 0 행은 빼되 쪽 넘김은 원래 행 수로 판단합니다.
  일시 오류로 끊기면 받은 데까지 남기고 다음에 이어 받으며, 그동안 기간 버튼 옆에 '더 앞 구간은 다음 스캔에서 이어 받음'.
- 리포트는 이력 파일의 이음매(리포트에 담긴 첫날)가 같은 가격일 때만 덧붙입니다 — 다르면(아직 옛 수정주가 기준) 1분 뒤 다시 봅니다.
- 파일로 직접 연 리포트(`file://`)는 브라우저가 옆 파일 읽기를 막아 담긴 기간(최근 약 3년)만 보입니다 —
  기업추적 뷰어의 '차트 발굴' 탭(`/tech/hist/<code>.json`)에서 열면 전체가 보입니다. 증권사 연결이 없으면 받아 둔 종목만.
- 증권사 자료라 이 PC 의 본인 분석용입니다(한국투자증권 Open API 약관: 시세는 본인 업무에만, 제3자 제공 금지).

### 종목 뉴스 제목 — `news` (기업추적 '내러티브' 탭용)

`python -m chart_screener news --codes 010170 [--pages 60] [--days 400] [--budget 120] [--per-sec 1.0] [--out DIR]` 는
한국투자증권 '종합 시황/공시(제목)'(FHKST01011800)을 종목마다 받아 `cache/kis/news/<code>.json` 에 쌓습니다
(`chart_screener/data/kis_news.py`, 형식은 맨 위 설명). 기업추적 뷰어가 하위 프로세스로 부르고 파일을 직접 읽어 분류합니다.

- 처음엔 최신부터 거꾸로 `--days` 일(또는 약 330일보다 앞에서 기사가 끝나 공시 제목만 남는 쪽)까지, 이후엔 새 제목만 받습니다.
  쪽 수 · 시간 한도에 걸리면 받은 데까지 저장하고 다음 실행에서 이어 받습니다(중소형주 1년치 약 44쪽 · 1분, 005930 은 하루 4쪽
  안팎이라 60쪽이 2~3주치). 시간 한도는 재시도 사이에도 지킵니다(한도 뒤로는 진행 중인 호출 하나만).
- 언론 기사는 증권사가 약 1년만 보관하므로 이 캐시는 행을 지우지 않습니다. 깨진 캐시는 `<code>.json.bad`(있으면 `.bad1` …)로
  치우고 새로 시작하며, 치우지 못하면(뷰어가 읽는 중 등) 그 종목은 이번에 받지 않습니다. 이 조회는 초당 1회 안팎이 한도라 따로 초당 1회로 부릅니다.
- 종료 코드 0 정상 · 1 증권사 연결 없음 / 인증 등 치명 오류 / 받으려 한 종목이 모두 실패(사유는 stdout 마지막 줄) · 2 인자 오류.
  기사 본문은 받지 않습니다. 언론사 저작물이라 본인 분석용입니다.

### 매일 자동 실행 (선택)

`scan_daily.bat` 은 멈춤·브라우저 없이 실행하고 `output/daily.log` 에 기록합니다. 장 마감 후 자동 실행하려면
명령 프롬프트에서 직접 등록하세요(경로는 본인 위치로).

```bash
schtasks /create /tn "chart_screener daily" /sc weekly /d MON,TUE,WED,THU,FRI /st 16:00 /tr "C:\경로\chart_screener\scan_daily.bat"
```

## 리포트 보는 법

- **헤더**: 시장 상태(상승 확인/상승 압박/조정, 분산일), 시장 폭(신고가−신저가, 50일선 위 비율) 스파크라인,
  증권사 자료 한 줄(`증권사 자료: 상태 2,449 · 실거래대금 2,449 · 수급 150 · 의견 150 · 실적 150 · 4분 12초`, 꺼졌으면 `증권사 자료 없음 — 네이버 (이유)`).
- **증권사 자료 열**(자료가 있을 때만): 종목명 옆 상태 칩(투자주의·투자경고·단기과열), `수급 20일`(기관+외국인 순매수),
  `목표가 괴리`(90일 증권사별 최신 목표가 평균 대비 종가, `↑N` = 30일 안 목표가 상향 수), `EPS(E) 성장`(선행 EPS 증가율).
  거래정지·정리매매·관리종목·투자위험 종목은 후보에서 빠지고 '탈락' 표에 `증권사 상태 제외: 관리종목` 처럼 사유와 함께 남습니다.
- **후보 탭**: 종합점수 순. 패턴 칩·단계·시장으로 거르고 `매수 검토 구간만`을 켜면 *돌파·피벗 근접* 중 매수 계획을 낼 수 있는
  대표만 남습니다(관찰 칩 · 손절 규칙 없는 신호 패턴 · 빗각 안착 확인 대기 · 거래량 미달 · 피벗 없는 결과 · 계획 '관망'은 뺌).
  배지(신규·단계상승·돌파·실패)는 직전 스캔 대비 변화입니다. 계좌 규모·위험%를 바꾸면 수량이 즉시 다시 계산됩니다.
- **300억 레이더 탭**: 최근 10거래일 안에 거래대금 300억↑·+7%↑ 양봉이 나온 종목과 50%선 유지 여부. 관심 목록이며 매수 신호가 아닙니다.
- **주도 업종·테마 탭**: 업종·테마별 RS 중앙값, 트렌드 템플릿 통과율, 신고가 수, 300억↑ 종목 수 순위와 대표 종목.
- **저평가 종목 탭** (저평가 목록 파일이 있을 때만, 아래 '저평가 종목 탭' 참고): 기업추적 저평가 목록 전 종목과 걸린 Tech 패턴. 관찰용.
- **차트**: 국내 관례대로 빨강=상승, 파랑=하락. 패턴 탭을 바꾸면 윤곽(컵 · 손잡이 상자)·피벗·컵 바닥·돌파 마커가 바뀝니다.

  | 당일 BREAKOUT_CONFIRMED (RVOL ≥ 1.4 · 종가 ≥ 진입가 · +5% 이내) | 거래량 확인이면 돌파. 비교 구간에 거래정지가 끼면 돌파로 세지 않음(아래 줄처럼) |
  | 당일 EXTENDED (종가 > 진입가 × 1.05 — 식은 거래량과 무관) | 이격 과다. 근거에 RVOL 통과 · 미달을 적음 |
  | 당일 PRICE_BREAKOUT · VOLUME_CONFIRMED_CLOSE_FAILED | 돌파 아님 — 종가로 피벗 근접 / 형성 중 + '식은 다음 봉부터 이 구조를 판정하지 않음' 경고. 장중 잠정이 아니면 실시간 감시에서 뺌(`attempt_consumed`) |
  | 당일 INVALIDATED (컵 바닥 이탈) | 탐지 안 함 (경고) |
  | 1~4봉 전 BREAKOUT_CONFIRMED (거래량 확인) | 지금 종가 < 피벗 × 0.97 돌파 실패 · > 진입가 × 1.05 이격 과다 · < 진입가 재시험(피벗 근접) · 그 외 돌파 (+ '식은 더 내지 않음 — Tech 5봉 창' 경고) |
  | 1~4봉 전 EXTENDED (거래량 확인) | 지금도 > 진입가 × 1.05 면 이격 과다, 매수 범위로 돌아왔으면 탐지 안 함 |

기업추적 `보컬.py`(눌림목 모드)와 같습니다. ①~③(거래대금 순위·테마 강도·대장)은 **전 시장 단면**이라 `scan` 이 한 번 세어
종목마다 넣고(약 2초), 단일 종목 `analyze`·`backtest` 에서는 판정하지 않습니다.

- 칩 '보컬 N' = 깔때기 ④~⑦ (기업추적 보컬 탭의 깔때기 표와 같은 범위). 급등 구간에 강한 테마의 대장·부대장이었는지는 근거에 적습니다.
- 단계: ④ 큰 상승·⑤ 눌림 = 형성 중, ⑥ 지지선 닿음 + 거래량 감소 = 피벗 근접, ⑦ 재유입 양봉 = 돌파(대장 · 손익비 1.5↑일 때만).
- 차트: 직전 고점(목표)·눌림 저점(손절)·닿은 지지선·급등 최대봉·⑦ 신호봉.
- **과거 검증은 손실**(위 표)이라 `scoring.BASE_PATTERNS` 에 넣지 않았습니다 — 종합 점수·진입 계획·`live` 감시 목록에 쓰이지 않고,
  대표 패턴이 보컬뿐인 종목은 '매수 계획을 내지 않음'으로 표시합니다.
- 잡주 거르기(원본과 같은 규칙): 네이버 분기 재무로 부채비율 200%↑·큰 적자(4분기 순손실 · ROE −10%↓)를 빼고(`cache/fin`, 7일 캐시),
  환경변수 `CHART_SCREENER_RISK_JSON` 에 기업추적 공시 위험 파일(`.cache/공시목록/공시위험.json`)이 있으면 작전주 꼴·상폐 절차·
  자금조달 잦음·관리종목 등도 뺍니다(기업추적 뷰어의 '차트 발굴' 탭은 자동으로 넘깁니다). 걸린 종목은 칩에서 빠지고 보컬 탭에 사유가 남습니다.
- 원본과 같게 맞춘 것: 패널은 60봉 이상(스캔 대상 120봉보다 짧은 신규 상장도 순위·테마·대장에 들어감), 장중 실행이면 미완성 봉을 빼고 어제까지로 잽니다.
- 차이: 거래대금은 Tech 일봉 value(과거는 추정치), 테마는 Tech 의 네이버 테마 분류표(오늘 것).
- `backtest vocal` 은 날마다 전 시장 단면이 필요해 지원하지 않습니다(검증은 기업추적 `도구/보컬_백테스트.py`).

### 저평가 종목 탭 (`undervalued`, 기업추적 저평가 목록)

기업추적 뷰어가 저평가 목록을 JSON 으로 쓰고 그 경로를 환경변수 `CHART_SCREENER_VALUE_JSON` 으로 넘기면
(`CHART_SCREENER_RISK_JSON` 과 같은 방식, 예: `기업추적/.cache/value/tech_export.json`) `scan` 이 한 번 읽어
종목마다 `ctx.info["undervalued"]` 에 넣습니다(`chart_screener/value_list.py`). 변수가 없거나 파일을 못 읽으면 탭 · 칩이 그냥 없습니다.

- 파일 양식(v1): `{"v":1, "at", "date":"YYYYMMDD", "source", "rows":[{"code","name","tier":"저평가"|"관찰","score","per","per_then",
  "per_pct","dd","roe","debt_eq","ni_yoy","px_yoy","industry","tier_why":[…],"risk"}]}` — 숫자는 null 가능, 코드는 6자리 문자열로 맞춥니다.
- 목록 종목은 **후보가 아니어도** 패턴 결과를 남깁니다(`ScanResult.value_scans`). 유동성 필터(20일 평균 거래대금 · 주가 · 시총) 밑인
  목록 종목도 패턴은 잽니다 — 저평가 종목은 소형주가 많아 문턱으로 자르면 등급 종목의 ⅓이 미판정이 됐다(2026-10-08: 127곳 중 44곳).
  이런 종목은 `StockScan.thin` 에 사유가 남고 **후보 · 300억 레이더에는 넣지 않으며** `분석 N종목` 수에도 세지 않습니다(표에 패턴이 없으면
  `패턴 없음 · 거래대금 적음`). 120봉 미만 · 종목 목록 밖만 `ScanResult.value_skipped` 에 사유와 종가가 남고 `패턴 미판정` 으로 나옵니다.
- 등급은 기업추적이 06:30 에 전날 스캔의 증권사 상태로 매긴 것이라, 스캔 때 받은 **그날 상태**로 거래정지 · 정리매매 · 관리종목 · 투자위험인
  '저평가' 행을 '관찰'로 다시 내립니다(`ValueList.apply_status`, 사유 `증권사 상태: …`).
- 증권사 자료가 켜져 있으면 목록 종목(분석된 것)도 수급 · 투자의견 · 추정실적을 후보와 같이 받습니다(같은 날 캐시).
- 탭 구성(기업추적 '저평가V2' 화면 모양): 범위 토글 `[저평가 등급 N | 관찰 포함 M]`(기본 저평가 등급만) → **셋업 카드**(목록 종목에 걸린
  Tech 패턴마다 종목 수 · 단계별 수, 누르면 표를 그 패턴으로 거름 — 지금은 컵 앤 핸들 · 보컬) → 표(기본 정렬 저평가 점수):
  종목(등급 배지 · 증권사 상태 · 공시 위험) · 업종 · 시가총액 · RS · 저평가 점수 · PER 1년 전→지금 · PER 자기 역사 · 고점 대비 · ROE · 부채비율 ·
  수급 20일 · 목표가 괴리 / EPS(E) 성장 · 걸린 패턴(단계) · 미니차트(최근 120봉 종가).
- 행을 누르면 차트: 후보는 전체 이력, 후보가 아닌 **저평가 등급**은 최근 약 250봉(탐지된 패턴 탭만 — 패턴이 하나도 없는 종목은 차트 없음,
  저평가 점수순 최대 120종목 `MAX_VALUE_CHARTS`), 그 밖(관찰 등급 · 미판정)은 미니차트만(리포트 크기). 차트 없는 행에 마우스를 올리면 이유가 보입니다.
  탭 배지 수 = 기본 범위(저평가 등급) 종목 수.
- **관찰용** — 점수 · 매수 계획에 안 들어갑니다. 과거 검증은 기업추적 `기술.py` 의 자체 셋업(이 리포트 칩과 다른 식)으로 잰 것:
  저평가 범위 안 바닥 투매 흡수 6개월 +3.4%p · 컵 12개월 +6~10%p(앞 기간 약함, 표본 수백 건). 지금 컵 앤 핸들(사용자 식)과 저평가를 함께 잰 적은 없습니다.

## 종합 점수

```
종합 = W × (0.55 × 대표 베이스 패턴 점수 + 0.20 × RS) ÷ 0.75 + 보너스      (≈ 0.73 × 패턴 + 0.27 × RS)
대표 = 피벗 있는 베이스 결과 중 위 식 × W 가 가장 큰 것 (컵 앤 핸들 · 빗각 · 피보 · 빗각+피보)
W(단계 가중치): 돌파 1.0 · 피벗 근접 0.95 · 형성 중 0.7 · 이격 과다 0.45 · 돌파 실패 0.15 (대표 없음 — 신호 · 관찰 칩만 0.6)
  덮어쓰기: 돌파 후 피벗 아래 재시험 0.6 · 묵은 돌파 0.7 · 손절폭 10% 초과(지금 매수 불가) 상한 0.7
보너스: 서로 다른 구조의 복수 베이스 +4~8 (피벗 있는 베이스만 · 빗각과 빗각+피보는 같은 구조) · 최근 5일 300억↑ +5 ·
        업종·테마 상위 10% +5 / 하위 20% −3 · 손절폭 15% 초과 −10 · 시장 조정 −10
체크리스트 10(검증 전) · 청산 계획 · 신호 패턴(60일선 · 월봉 적삼병) · 관찰 칩은 점수에 넣지 않는다.
```

- 패턴 점수는 모듈마다 정한 '구현 선택' 점수입니다(성공 확률 아님) — 컵 앤 핸들 `quality_score`, 빗각 = 기울기 · 접점 · 거래량 등 가중합,
  피보 = 장대양봉 몸통 · 거래량 · 라인 깊이 · 반등 거래량. 서로 다른 식의 점수라 같은 눈금이 아닙니다(검증 전).

- 2026-10-14: 옛 '기술적 체력'(트렌드 템플릿 · CAN SLIM, 0.25) · 추세·RS 약함 감점 · 주도주(베이스 없음) · 패턴별 덮어쓰기
  (300억 눌림목 · 장기횡보 · CAN SLIM) · 포켓 피벗 보너스를 그 탐지기와 함께 뺐습니다. 남은 가중치는 합이 1 이 되게 다시 나눈 것이며
  **검증된 값이 아닙니다** — 새 식이 더 들어오면 다시 정합니다. 리포트 상세의 점수 줄은 실제로 쓴 가중치를 보여 줍니다.

- **RS 레이팅**: IBD 방식(최근 3개월 40%, 이전 3개 분기 각 20%) 가중 수익률의 전 종목 백분위(1~99).
- **시장 방향(M)**: 분산일(−0.2%↓ & 거래량 증가, 25일 유효), 랠리 시도 4일차 이후 팔로스루데이(KOSPI +1.25%, KOSDAQ +1.5%),
  랠리 저점 이탈 시 FTD 무효, 시장 폭(신고가−신저가 10일 평균) 약화 시 점수 하향.
- **수급**: 증권사 자료가 켜져 있으면 **후보 전부**에 한국투자증권 투자자별 순매수(30일, 체결 금액)를 붙여 20일 기관·외국인 순매수를
  표시합니다(점수에는 안 씀 — 예전 CAN SLIM I 재계산은 2026-10-14 제거). 꺼져 있거나 증권사 수급이 없는 종목은 상위 60개 후보에
  네이버 순매매(주식수 × 종가)를 씁니다.
- **업종·테마**: 네이버 업종·테마 구성 종목(월 1회 갱신 캐시)으로 그룹 강도를 계산합니다.

## 증권사(한국투자증권) 자료 — 일일 스캔

`scan` 은 기본(`--kis auto`)으로 한국투자증권 Open API 시세 조회를 같이 씁니다 (아래 '실시간 연동'의 설정 파일과 같음, 조회 전용).
설정·토큰이 안 되면 이유를 보여 주고 예전처럼 네이버 자료로만 스캔합니다. 클라이언트 하나(초당 15회 제한)를 8개 작업 스레드가 같이 쓰고,
결과는 `cache/kis/` 에 거래일별 JSON 으로 캐시해 같은 날 다시 돌리면 거의 요청하지 않습니다 (`chart_screener/kis_scan.py`, `data/kis_market.py`).

| 단계 | 대상 | 쓰는 곳 |
|---|---|---|
| 종목 상태 (`inquire-price`) | 전 종목 | 거래정지·정리매매·관리종목·투자위험 → 후보 제외('탈락' 표에 사유), 투자주의·경고·단기과열 → 이름 옆 칩 (증거금100%는 전 종목의 68%라 칩으로 안 씀) · 외국인 보유율(`frgn_hldn_qty ÷ lstn_stcn` — `hts_frgn_ehrt` 는 한도 대비 소진율이라 쓰지 않음) |
| 실제 거래대금 (일봉, 처음 100거래일 → 매일 누적) | 전 종목 | 추정 거래대금 `(고+저+종)/3×거래량` 을 덮어씀 → 패턴·유동성 필터·시장 폭·업종 강도·300억 레이더·보컬 순위가 실제 값 사용 |
| 수급 (`inquire-investor`, 30일) | 후보 전부 + 저평가 목록 종목 | 20일 기관·외국인 순매수 표시 (후보 중 실패 종목은 네이버로 대체) |
| 투자의견 (`invest-opinion`, 180일) | 후보 전부 + 저평가 목록 종목 | 30일 리포트 수 · 목표가 상향/하향 · 90일 평균 목표가 대비 괴리 |
| 추정실적 (`estimate-perform`) | 후보 전부 + 저평가 목록 종목 | 선행 EPS 증가율 · 추정 EPS |

- 스캔이 끝나면 단계별 건수·시간을 콘솔에 찍고, 스냅샷 JSON 을 **스캔 출력 폴더 `kis_snapshot.json`** 과
  **고정 경로 `cache/kis/snapshot.json`**(기업추적 뷰어용) 두 곳에 씁니다. 형식은 `data/kis_market.py` 맨 위 설명 참고.
- 첫 실행은 전 종목 상태·거래대금 약 4,900회 + 후보 수십~수백 회 요청입니다. 2026-10-09 실측 약 16분 — 서버가 초당 약 5건부터
  `EGW00201`(초당 한도)을 돌려줘서, 스캔 중에는 호출 한도를 초당 12회로 낮추고(`kis_scan.SCAN_PER_SEC`) 실패 종목은 2스레드로 한 번 더 받습니다.
  같은 기준일 재실행은 캐시를 써서 거의 요청하지 않고, 다음 날부터 거래대금은 마지막 날짜 이후만 받습니다.
- 앱키 오류·토큰 거부 같은 치명 오류, 캐시 쓰기 실패(드라이브 잠김) 같은 예기치 못한 오류가 나면 그 단계에서 증권사 자료를 끄고 나머지는
  네이버로 계속하며, 헤더에 `중단: 사유` 를 남깁니다(멈춘 단계는 성공 수 0 · `중단`). 일자별 캐시 저장만 실패하면 받은 자료는 그대로 씁니다.
- 캐시 신선도: 종목 상태는 장중(개장일 08:00~15:45)엔 **오늘 3시간 안**에 받은 것만, 장 밖에선 받은 뒤 개장일 08:00 · 15:45 를
  지나지 않았으면 다시 씁니다(장중 스캔이 전날 저녁 상태를 쓰지 않게, 저녁 · 휴장일 재실행이 전 종목 상태를 다시 받지 않게 — 2,449건 약 11분).
  다시 받다 실패한 종목은 묵은 상태라도 씁니다(관리 · 정지 종목이 상태 없음으로 후보에 들어가지 않게). 기준일 거래대금은 18:10
  (시간외 단일가까지 더해진 뒤) 전에 받았으면 18:10 이후 실행에서 한 번 더 받습니다. 수급은 18:10 이후 받은 것만 재사용.
- 개장일: 한국투자증권 휴장일 조회가 답하지 못하면(모의투자 · 조회 실패) 내장 KRX 달력으로 판단합니다. `--skip-holiday` 는 KOSPI 일봉
  캐시의 마지막 봉이 종가 확정(15:45) 전에 받은 장중 봉이면 직전 개장일 종가로 치지 않고 스캔합니다.
- 실제 거래대금은 최근 약 100거래일(이후 매일 누적)만 있고, 그 앞은 여전히 추정치입니다. 보컬 단면에 넣는 짧은 신규 상장(60~119봉)에도 받은 실제 거래대금을 덮어씁니다.

## 증권사(한국투자증권) 실시간 연동

스캔으로 찾은 후보를 장중 실시간 시세로 감시해 **피벗 근접·돌파·눌림 구간 진입·손절가 이탈**을 알려 줍니다.
**조회 전용**입니다 — 주문(매수·매도) 기능이 없고, 증권사 API 는 시세 조회와 실시간 체결가만 씁니다.
HTS(eFriend Plus)를 켜 둘 필요는 없습니다. 같은 계정으로 발급받는 **KIS Open API**(REST·웹소켓)로 시세를 받습니다.

### 1. 준비 (처음 한 번)

1. 한국투자증권 계좌로 [KIS Developers](https://apiportal.koreainvestment.com) 에서 Open API 를 신청하고
   **앱키(App Key, 보통 36자)·앱시크릿(App Secret, 보통 180자)** 을 발급받습니다.
2. `C:\Users\<사용자>\KIS\config\kis_devlp.yaml` 에 공식 샘플(open-trading-api) 양식으로 저장합니다.
   다른 위치면 환경변수 `CHART_SCREENER_KIS_CONFIG` 또는 `--config` 로 지정하세요. 필요한 항목:

   ```yaml
   my_app: "발급받은 앱키"
   my_sec: "발급받은 앱시크릿 — 줄바꿈 없이 한 줄"
   my_acct_stock: "계좌번호 앞 8자리"      # 시세 조회에는 필요 없음
   my_prod: "01"
   prod: "https://openapi.koreainvestment.com:9443"
   ops: "ws://ops.koreainvestment.com:21000"
   ```

3. `pip install -r requirements.txt` (웹소켓용 `websockets` 포함).
4. 점검: `python -m chart_screener live --check` — 설정 형식 → 접근토큰 → 현재가 → 개장일 → 웹소켓 순서로 ✔/✘ 와 이유를 보여 줍니다.
   예시 문구가 그대로인 경우(`my_sec 이 예시 문구 그대로입니다 (한글 포함, 6자)`), 시크릿이 잘린 경우(길이),
   공백·줄바꿈·따옴표가 섞인 경우, 앱키와 시크릿이 뒤바뀐 경우를 **값은 보여 주지 않고** 알려 줍니다.
   KIS 오류 코드도 한글로 바꿉니다 (`EGW00105` 앱시크릿 오류, `EGW00103` 앱키 오류, `EGW00133` 토큰 1분 1회 한도).

### 2. 실행

`live.bat` 더블클릭, 또는:

| 명령 | 하는 일 |
|---|---|
| `python -m chart_screener live` | 자동: KIS 설정·토큰이 되면 KIS 실시간, 아니면 이유를 알리고 네이버 시세(10초 간격) |
| `python -m chart_screener live --source kis` | KIS 만 (안 되면 이유를 보여 주고 종료) · `--source naver` 는 네이버만 |
| `python -m chart_screener live --top 20 --codes 003490,005930` | 감시 종목 수, 꼭 볼 종목(피벗이 있는 스캔 후보) |
| `python -m chart_screener live --venue total` | KRX+NXT 통합 체결가 (기본은 KRX — 일봉·50일 평균과 같은 기준) |
| `python -m chart_screener live --no-toast --beep --no-open` | 윈도우 알림 끄기 · 소리 · 브라우저 안 열기 |
| `python -m chart_screener live --after-hours` | 장 시간 밖에도 실행 (점검·시험용) |

- 시작하면 스캔(장 마감 후 받은 캐시가 있으면 캐시만 — 2026-10-14 실측 적재 포함 약 2분, 그중 패턴 판정 약 45초)으로
  감시 목록을 최대 40종목 고릅니다:
  돌파·피벗 근접 → '피벗 X 돌파 매수' 대기 순(같은 순위는 종합점수 순). 손절가가 없는 컵 앤 핸들은 돌파 · 피벗 근접일 때만
  감시하고 `[손절]` 알림이 없습니다(형성 중은 진입 계획이 없어 감시하지 않음). 확인 안 된 돌파 시도(가격만 돌파 · 종가 미달)로
  식에서 끝난 구조는 '피벗 근접'이어도 감시하지 않습니다 — 식은 그 다음 봉부터 그 구조로 돌파를 판정하지 않습니다.
  돌파 실패·이미 손절가 아래인 종목은 뺍니다. **전날 장 마감 후 `scan` 을 한 번 돌려 두면** 아침에는 캐시로 바로 시작합니다.
- 09:00 전에 켜면 카운트다운 뒤 시작하고, 15:30 장 마감 뒤 자동 종료합니다. Ctrl+C 로 언제든 끌 수 있습니다.
- 주말·KRX 휴장일(내장 달력, KIS 연결 시 한국투자증권 국내휴장일조회 — 결과를 캐시해 하루 1회만 조회)에는 바로 끝납니다.
  달력에 없는 휴장일은 10:15 까지 오늘 체결이 하나도 없으면(지난 거래일 시세만 오면) 휴장일로 보고 끝냅니다.
- `output/live.html` 대시보드(3초마다 자동 새로고침)가 브라우저로 열립니다:
  종목 · 현재가 · 등락률 · 패턴/단계 · 피벗까지 % · 손절가 · 거래량 예상배수 · 마지막 알림 · 갱신 시각.

### 3. 알림의 뜻

| 알림 | 조건 | 볼 것 |
|---|---|---|
| `[근접]` | 현재가가 피벗 -1% 이내 (`--near`) | 돌파 매수(역지정가) 준비 |
| `[돌파]` | 현재가 > 피벗. 전일 종가가 피벗 이하였거나, 장중 피벗 아래로 되밀렸다 다시 넘을 때 | `거래량 1.8배 예상 ✓` = 누적 거래량 ÷ 장중 경과 비율(U자형) ÷ 50일 평균 ≥ 1.4배(`--vol-mult`). `✘` 면 거래량 미확인 돌파 |
| `[눌림]` | 매수 구간(지정가 하한 ~ 상단) 진입 — **지금은 이 구간을 채우는 패턴이 없어 나오지 않음** (예전 300억 눌림목, 2026-10-14 제거) | 지정가 매수 구간. 손절은 **종가** 기준 |
| `[손절]` | 현재가 ≤ 손절가 (손절가 위에 있다가 내려올 때) | 손절 검토. 아직 매수 전(진입 계획이 '피벗 … 돌파 매수'·재돌파 대기)이면 매수 계획 보류 |

- 예: `[돌파] 대한항공 30,950 (피벗 30,900) · 거래량 1.6배 예상 ✓ · 잠정 — 종가가 피벗 위인지 확인`
- 알림은 **종목·종류별 하루 1회**이며 `output/live_alerts_YYYYMMDD.csv` 에 남아 다시 실행해도 반복하지 않습니다.
  이 파일을 엑셀로 열어 둬서 쓸 수 없으면 `live_alerts_YYYYMMDD.pending.csv` 에 대신 기록하고 한 번 안내합니다.
- **손절가를 깬 종목은 그날 `[근접]`·`[돌파]`·`[눌림]` 을 더 내지 않습니다** (전일 종가가 이미 손절가 이하인 종목 포함).
  대시보드 손절가 칸에 '손절 이탈 — 매수 알림 끔' 으로 표시됩니다. (옛 장기횡보 돌파처럼) 손절가가 피벗보다 위인 종목이
  손절가 → 피벗 아래로 밀렸다 다시 오를 때 '손절 뒤 돌파' 같은 모순된 알림이 나지 않게 하기 위함입니다.
- **오늘 정규장 체결만** 알림에 씁니다. 첫 체결 전 네이버 시세(전 거래일 15:30 시각), 09:00 전 시세, 누적 거래량 0 인
  현재가는 대시보드에 '지난 시세' 로만 보여 줍니다.
- **장중 신호는 모두 잠정**입니다. 거래량 배수는 시간대별 거래량 비율 추정이라 장 초반(09:15 전)에는 부정확합니다.
  돌파는 종가가 피벗 위에서 끝났는지 확인하세요 (컵 앤 핸들 식의 돌파 확인 = 종가 ≥ 진입가 · 거래량 1.4배).

### 4. 한계

- 실시간 구독은 세션당 **최대 40종목**으로 알려져 있지만, 계정·시간대에 따라 훨씬 적을 수 있습니다
  (2026-10-08 장 마감 후 실측: 세션당 3종목, 4번째부터 `OPSP0008 MAX SUBSCRIBE OVER`).
  서버가 거부한 종목과 40종목 상한 밖 종목은 **REST 현재가 조회(15초 간격)로 자동 보충**하므로 감시는 빠짐없이 됩니다.
  시작할 때는 감시 종목 전체 현재가를 한 번 받아 두어, 체결이 뜸한 종목도 처음부터 가격이 보입니다.
- 같은 앱키로 다른 실시간 프로그램을 동시에 쓰면 접속이 거부될 수 있습니다.
- 접근토큰은 **1분에 1회** 발급되고 발급할 때마다 알림톡이 옵니다 → 토큰(유효 24시간)을 저장해 재사용하고 만료 10분 전에 새로 받습니다.
- REST 는 초당 15회(모의투자 `--paper` 는 2회) 이하로 부르고 `EGW00201`(초당 한도)이면 쉬었다 다시 부릅니다.
  웹소켓이 끊기면 1→60초 간격으로 다시 접속·재구독하고, 5회 연속 실패하면 REST 현재가 조회(15초 간격)로 바꾼 뒤
  **5분마다 웹소켓을 다시 시도**합니다. 접속키 거부·'이미 접속 중' 응답이면 연결을 닫고 다시 접속합니다.
- 네이버 시세는 공개 웹 API 를 조회하는 방식이라 수 초 지연되고, 네이버가 형식을 바꾸면 동작하지 않을 수 있습니다.
  3회 연속 실패하면 전 종목 목록 API(1분 간격)로 바꾸고 **3분마다 원래 방식을 다시 시도**해 되면 돌아옵니다.
- 피벗·손절가·단계는 마지막 스캔(보통 전일 종가) 기준이며 장중에 다시 계산하지 않습니다.
- 감시하는 패턴은 컵 앤 핸들(사용자 식, `scoring.LIVE_PATTERNS`)뿐입니다. 《차트의 기술》 기법은 검증 전이고 장중 '돌파' 뜻이 기법 규칙과
  달라(피보 신호 뒤 피벗 = 진입가, 빗각 돌파 확인 = 종가 · 안착 확인) 넣지 않았습니다 — 넣으려면 기법마다 알림 규칙을 따로 정해야 합니다.

### 5. 보안

- 앱키·시크릿·토큰·접속키는 화면·로그·대시보드·CSV·오류 메시지에 출력하지 않습니다 (앱키 앞 4글자와 길이만).
- 설정 파일과 토큰 캐시(`~/KIS/config/chart_screener_token.json`, 개장일 캐시 `chart_screener_holidays.json`)는 저장소 **밖**에 둡니다. 실수로 복사해 와도 커밋되지 않게
  `.gitignore` 에 `kis_devlp.yaml`·`*token*.json` 을 넣어 두었습니다. 설정 파일을 남에게 보내거나 화면 공유하지 마세요.
- 시크릿이 노출됐다고 생각되면 KIS Developers 에서 재발급하세요. 이 도구에는 주문 기능이 없지만, 같은 키로 다른 프로그램은 주문할 수 있습니다.

## 데이터와 한계

- 출처: 네이버 금융 (종목 목록·일봉·투자자별 매매·업종/테마). KRX 정보데이터시스템은 로그인이 필요해 쓰지 않습니다.
- 가격은 **수정주가**, 거래량은 **원 거래량**(미수정)입니다. 베이스 안에 액면분할이 있으면 거래량 배수가 왜곡될 수 있어
  거래정지일이 패턴 구간에 있으면 경고합니다. 거래량 0 인 정지일은 자동 제거합니다. 스팩·우선주·리츠는 제외합니다.
- 과거 일별 거래대금은 `(고+저+종)/3 × 거래량` 추정치이고, 당일 값은 실제 집계치로 교체합니다.
  증권사 자료가 켜져 있으면 최근 약 100거래일(누적)은 한국투자증권 실제 거래대금으로 바뀝니다.
- 장중 실행 시 마지막 봉은 미완성입니다(종목목록을 받은 시각 기준 판정). 시간대별 누적 거래량 비율(U자형)로 하루치를 환산하며
  리포트에 "장중"으로 표시됩니다. 확정 판단은 장 마감(15:45) 이후 실행을 권장합니다.
- 일봉 이력은 약 3년(750봉)이라 '역사적 신고가'는 그 범위 안의 고점입니다.

### 새 패턴 추가

`chart_screener/patterns/새패턴.py` 에 `@register("이름", "표시명")` 을 붙인 `detect(ctx) -> PatternResult` 를 만들면
스캔·리포트·백테스트에 자동 포함됩니다. `undervalued.py` 가 가장 짧은 예시, 외부 식을 감싸는 예시는 `cup_with_handle.py` 입니다.
베이스 패턴으로 점수에 넣으려면 `scoring.BASE_PATTERNS` 에, 손절 규칙 없는 신호는 `SIGNAL_PATTERNS`(+ 혼자 후보가 되는 단계
`SIGNAL_CANDIDATE_STAGES`), 관찰 칩은 `OBSERVE_PATTERNS` 에 이름을 추가하세요(리포트 칩 순서 · 탭 순서가 따라감). 키는 옛 패턴 이름(위 '제거된 패턴')을 다시 쓰지 마세요 —
일지 · 기록 채점에서 옛 기록과 섞입니다. 일지 `rule` 칸은 `metrics['rule_version']`(규칙을 바꾸면 버전을 올림).
백테스트 사전 필터는 신호를 놓치지 않는다는 검증 뒤에만 `backtest.PREFILTER` 에, 신호일이 `breakout_date` 와 다르면 `backtest.event_date`,
손절 판정이 '저가 ≤ 고정 손절가'가 아니면 `backtest.STOP_RULE` 에 넣습니다. 리포트 수치 라벨은 모듈의 `METRIC_LABELS`(있으면 자동) 또는 템플릿 `MLABEL`.

### 2단계(저평가) 연결 지점

지금은 기업추적 저평가 목록을 정보 칩(`undervalued`)으로만 붙입니다(점수에 안 씀). 재무 자료를 점수에 넣으려면 수급 보강
(`scanner.enrich_investor`)과 같은 방식으로 상위 후보에만 자료를 붙이고 `scoring.compute` 에 항목을 더하세요 — 그 전에 효과를 검증할 것.
(예전 CAN SLIM 의 C·A 연결 지점은 2026-10-14 CAN SLIM 과 함께 제거.)
